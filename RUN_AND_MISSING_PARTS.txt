LOGBOOK - RUN GUIDE AND MISSING PARTS
======================================

This file explains how to run the current project locally and what still needs to be completed before production use.


1. REQUIREMENTS
---------------

Install these tools on Windows:

- XAMPP with Apache, MySQL, PHP, and phpMyAdmin
- Node.js LTS and npm
- A modern browser
- Optional: Git

Recommended local URLs:

- React frontend: http://localhost:5173
- PHP API: http://localhost/logbook/backend/api
- phpMyAdmin: http://localhost/phpmyadmin


2. COPY THE PHP BACKEND INTO XAMPP
----------------------------------

The PHP backend must be inside Apache's web directory.

1. Open:
   C:\xampp\htdocs

2. Create a folder named:
   logbook

3. Copy this project's backend folder into it:
   C:\xampp\htdocs\logbook\backend

The final API bootstrap file should exist here:

C:\xampp\htdocs\logbook\backend\api\bootstrap.php

Do not put the React frontend inside htdocs for normal development. Run React with Vite instead.


3. START XAMPP
--------------

1. Open the XAMPP Control Panel.
2. Start Apache.
3. Start MySQL.
4. Confirm both services show as running.

If Apache cannot start, another program may already be using port 80. Either stop that program or change the Apache port and update the API URL accordingly.


4. CREATE THE DATABASE
----------------------

Option A: phpMyAdmin

1. Open http://localhost/phpmyadmin
2. Select the Import tab.
3. Import:
   database/schema.sql
4. Import:
   database/seed.sql

The seed file creates an administrator account:

Email: admin@example.com
Username: admin
Password: password

Change this password immediately after testing. Do not use it in production.

Option B: MySQL command line

From the project root, run a command similar to this if the mysql command is available:

mysql -u root -p < database/schema.sql
mysql -u root -p logbook < database/seed.sql

For a default XAMPP installation, the MySQL root password is often blank. If your installation has a password, enter it when prompted.


5. CREATE THE PHP ENVIRONMENT FILE
-----------------------------------

The example file is:

backend/.env.example

Create a real file named:

backend/.env

Copy the example values into it and update them for your machine:

DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=logbook
DB_USERNAME=root
DB_PASSWORD=
APP_ORIGIN=http://localhost:5173
SESSION_NAME=logbook_session
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
GOOGLE_REDIRECT_URI=http://localhost/logbook/backend/api/auth/google.php

Important:

- backend/.env must never be committed to Git.
- Database credentials belong only in the PHP backend.
- Never add DB_HOST, DB_USERNAME, DB_PASSWORD, or DB_DATABASE to frontend/.env.
- The PHP code reads backend/.env through backend/config.php.


6. INSTALL AND RUN THE REACT FRONTEND
--------------------------------------

Open PowerShell in the project root:

cd "C:\Users\ADMIN\Desktop\VSCODE PROJECTS\Interactive_LogBook_WebApp\frontend"

Install dependencies:

npm install

Create the frontend environment file:

Copy-Item .env.example .env

The local frontend/.env should contain:

VITE_API_URL=http://localhost/logbook/backend/api

Start the development server:

npm run dev

Open the URL printed by Vite, normally:

http://localhost:5173

To verify a production build:

npm run build


7. BASIC LOCAL TESTING
----------------------

Test the following in order:

1. Open the React URL.
2. Create a new user account.
3. Sign out and sign in again.
4. Confirm the account is stored in the users table.
5. Sign in as the seeded admin account.
6. Confirm the PHP API can be reached at:
   http://localhost/logbook/backend/api/
7. Test creating, listing, updating, and deleting log records.
8. Test that a normal user cannot call admin endpoints successfully.
9. Test the layout at desktop and mobile widths.

If the browser reports a CORS error, confirm APP_ORIGIN exactly matches the React URL, including the port.

If the browser reports a database error, check that MySQL is running and that backend/.env matches the XAMPP database credentials.

9. MISSING OR INCOMPLETE PARTS
------------------------------

These items need to be completed before calling the application production-ready:

A. Connect every dashboard action to the API

The React dashboard currently has demo fallback log records and local state for the add-entry modal. The UI should be updated to:

- Load /logs/list.php after authentication.
- Submit new records to /logs/create.php.
- Refresh records after create, update, and delete.
- Display server errors and session-expired errors.
- Remove demo records when the API is available.

B. Complete the React routes and pages

The current app has the main dashboard and login/register experience. Add dedicated pages for:

- /logs
- /logs/create
- /logs/:id
- /logs/:id/edit
- /profile
- /settings
- /forgot-password
- /reset-password
- /admin
- /admin/users
- /admin/users/:id
- /admin/logs
- /admin/activity
- /admin/settings

C. Complete Google OAuth

The Google OAuth endpoint is not yet implemented. It must:

- Redirect to Google's authorization URL.
- Validate the returned state value.
- Exchange the authorization code server-side.
- Validate the ID token using Google's supported library or endpoints.
- Find or create the local user using google_id.
- Create the PHP session.
- Redirect back to the frontend safely.
- Keep GOOGLE_CLIENT_SECRET only on the PHP server.

D. Complete password reset

Implement:

- Forgot-password endpoint.
- Cryptographically random reset token.
- Hashed token stored in password_resets.
- Expiration validation.
- Email delivery through a configured mail provider.
- One-time token invalidation after use.
- Reset-password endpoint.

Never return reset tokens in normal API responses in production.

E. Add CSRF protection

Because authentication uses cookies and PHP sessions, add CSRF protection for state-changing requests:

- Generate a server-side CSRF token.
- Return it through an authenticated endpoint.
- Send it in X-CSRF-Token from React.
- Validate it in PHP for POST, PUT, and DELETE requests.
- Use secure, HttpOnly, SameSite cookies in production.

F. Add rate limiting and account protection

Add server-side protection for:

- Login attempts.
- Registration attempts.
- Password reset requests.
- Google OAuth callback abuse.

Record attempts by IP address and account identifier, and use a suitable cache or database strategy.

G. Complete admin UI

The backend admin endpoints exist, but the React admin pages and controls still need to be built. Include:

- User search and pagination.
- User role changes.
- Activate/deactivate controls.
- User detail and user logs.
- All-log search, filters, and pagination.
- Activity log viewer.
- Confirmation dialogs for destructive actions.
- Protection against removing the current admin's own access.

H. Improve backend validation

Add strict server-side validation for:

- Date and time values.
- Allowed categories.
- Allowed statuses.
- Maximum text lengths.
- Date range filters.
- Pagination limits.
- Sort field allowlists.

Never use a user-provided SQL column name directly. Use an allowlist.

I. Production security configuration

Before deployment:

- Use HTTPS.
- Set secure and HttpOnly session cookies.
- Set SameSite appropriately.
- Restrict CORS to the real Vercel domain.
- Disable PHP display_errors in production.
- Log technical errors privately on the server.
- Configure backups for MySQL.
- Rotate all development credentials.
- Change the seeded admin password or remove seed.sql data.
- Verify backend/.env is outside public downloads where possible.

J. Activity logging

Write activity_logs records for important actions:

- Login and logout.
- Registration.
- Create, update, and delete log.
- Admin role changes.
- User activation/deactivation.
- Password reset.

Do not store passwords, OAuth secrets, or reset tokens in activity logs.


10. PRODUCTION DEPLOYMENT OVERVIEW
----------------------------------

Frontend:

1. Push the project to a Git provider.
2. Import the frontend folder into Vercel.
3. Set the Vercel build command to npm run build.
4. Set the output directory to dist.
5. Add this environment variable in Vercel:
   VITE_API_URL=https://your-api-domain.com/api

Backend:

1. Use a PHP-compatible host with HTTPS.
2. Upload the backend folder.
3. Create a production backend/.env outside version control.
4. Point DB_* variables to the cloud MySQL database.
5. Set APP_ORIGIN to the exact Vercel domain.
6. Import database/schema.sql into the cloud database.
7. Configure PHP sessions and HTTPS cookies.
8. Test the API from the deployed Vercel frontend.

Google OAuth:

1. Add the production callback URL in Google Cloud Console.
2. Set GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET, and GOOGLE_REDIRECT_URI on the PHP host.
3. Confirm the callback does not expose the client secret.
4. Test both first-time Google registration and returning Google login.


11. IMPORTANT LIMITATION
------------------------

The project is a working development scaffold with a functional PHP authentication/log API and a polished React dashboard. It is not yet a complete production release until the missing items above are implemented and tested against a real MySQL database, real HTTPS hosting, and configured Google OAuth.
